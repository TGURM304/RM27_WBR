# RM27_WBR 项目背景与约束

本文件保存项目背景、当前阶段目标和数据约定，供后续讨论与开发使用。已确认的需求与待确定的实现细节分别记录；修改约定时同步更新本文件。

## 项目背景

本项目基于 STM32H723、FreeRTOS 和 CMake 开发二自由度腿部的轮腿机器人。按开发者说明，DM8009P 关节电机、DJI M3508 电机驱动及 IMU/INS 已完成当前阶段的开发，接下来建立驱动反馈到建模数据之间的映射。

当前重点是统一电机与机体状态的零点、正方向、单位和角度表达，使后续运动学、状态计算与控制使用模型约定的数据。驱动可提供反馈，不代表这些反馈已经符合模型定义；本文也不把代码阅读视为硬件验证。

## 已确认的数据约定

### 关节零点

关节电机的零度角由开发者在 `chassis_data_conifg.h` 中定义，软件据此把电机反馈映射到建模使用的关节角。本文不重新规定零姿态，也不要求重新推导杆件在零姿态时的方向。

关节软件归零属于模型数据映射，不隐含修改电机硬件零点。后续实现需明确配置偏置在公式中的含义，并使零角、正方向、角速度方向与模型一致；不能只根据 `offset` 这个名字决定加减号。

### IMU 零点

IMU 使用固定安装姿态与机体姿态之间的关系建立模型参考，不把每次上电时的任意姿态作为机体零姿态。

固定安装补偿与陀螺仪静态零偏校准是两项不同工作：前者定义坐标关系，后者修正角速度测量偏差。现有 INS 的 `imu calibrate` 处理陀螺仪零偏，不能替代机体安装姿态补偿。

### 归一化的含义

这里的归一化指统一单位、正方向、坐标系和角度区间。后续计算保留物理量，不统一缩放成 `[-1, 1]` 或 `[0, 1]`。

| 量 | 模型数据使用的单位 |
| --- | --- |
| 关节角、轮转角、机体姿态角 | rad |
| 角速度 | rad/s |
| 位移、腿长、轮半径 | m |
| 线速度 | m/s |
| 加速度 | m/s² |
| 涉及的力矩 | N·m |

上述单位不代表本阶段必须把所有量都加入 `chassis_basedata`；只增加后续实际需要的结果。

## 当前阶段的职责与限制

1. 驱动负责设备协议、反馈解码和已有的设备单位换算；底盘数据观察器负责把反馈映射到模型约定。模型的零点、方向和坐标约定集中表达，后续计算不再各自补偿一次。
2. 已完成的单位或减速比换算不重复执行。当前 DJI `feedback.angle`、`feedback.speed` 已按 `ratio` 换算为输出轴 rad、rad/s；INS 欧拉角已是 rad。若轮侧另有传动，应明确驱动 `ratio` 已覆盖的范围，再决定剩余换算。
3. 电机角度回绕、连续角累计、软件偏置和无量纲缩放是不同操作。关节使用的角度区间按模型确定；需要连续位移的轮角保留跨圈信息，不能先压回单圈再当作总位移。
4. 关节角与角速度使用一致的方向定义。固定角度偏置不直接加到角速度上；多轴姿态补偿应按坐标变换处理，不能把任意安装旋转都简化成三个欧拉角相减。
5. 姿态、角速度、加速度需说明所属坐标系；若 INS 已通过 `ins::init(trans)` 完成安装坐标变换，观察器不重复执行同一变换。陀螺仪各轴角速度与欧拉角变化率也不能无条件视为同一量。
6. 当前 INS 的 `accel` 是经安装矩阵变换的加速度计读数，代码没有进行重力扣除。后续若需要用于平移计算的加速度，应先定义表达坐标系和重力处理，再提供对应结果。
7. 欧拉角倾倒奇异问题不能靠零偏消除。头文件已有姿态向量的设想；实际使用时需定义向量含义、参考轴及坐标系，四元数也需确认旋转方向，不仅凭字段名直接套用。
8. 本阶段先保存背景、约束与待定项，不直接补写观察器、控制器、VMC 或 LQR。后续模块以实际需求增加，不预建通用框架，也不照搬旧项目的数值、符号和调用流程。

## 实现前需要补齐的具体约定

以下内容尚未定值，不影响当前背景文档成立；实现对应计算前必须明确。

- `J1_offset` 至 `J4_offset` 与具体设备、侧别、前后关节的绑定，以及各关节正方向。现有布局图确定空间编号，但没有证明它与 CAN 配置、指针字段之间的完整对应关系。
- `comp_ptr` 中 `lef_forward`、`lef_back`、`right_forward`、`left_back` 的实际对应关系。字段命名存在歧义，不能据此猜测左右后关节绑定。
- IMU 固定安装变换的数值与方向、由 INS 还是观察器承担，以及模型姿态轴和 `body_theta`、`body_phi`、`body_roll` 的明确对应关系。
- 各姿态角、关节角使用的区间；轮转角、位移与航向中哪些需要连续累计，哪些需要相对参考。
- 实际轮半径、减速比及传动覆盖范围。当前 `WHEEL_REDUCTION_RADIUS` 名称不能直接证明其代表半径还是传动比。
- 数据更新时间与读取方式。CAN、INS 在不同执行上下文更新，公开指针不等于同一时刻的完整快照；按实际调用链约定采样和一致性，不预设新增任务或锁。

## 个人实现习惯

按开发者指定的 `author-control-style` 资料，后续实现遵循：职责集中、依赖显式、只保留下一次真正需要的状态；无状态变换直接使用函数，需要零点或历史时再保存成员。

接口集中说明单位、方向、调用前提与结果含义。边界由职责所有者处理，不逐层重复检查；不为仿写增加无实际用途的 getter、缓存、管理器和故障流程。命名贴近模型与物理量，中文注释补充约定，排版服从工程已有规则。
